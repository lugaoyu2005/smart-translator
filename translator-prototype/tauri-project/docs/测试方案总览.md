# 测试方案总览

> 项目：智能翻译软件（Tauri v2 = React18+TS 前端 / Rust 后端）
> 更新：2026-09-09。测试共 **134 个自动化用例**（Rust 94 + 前端 40），全部通过。

## 一、快速上手

```bash
cd translator-prototype/tauri-project

npm test              # 健全性 + Rust 全套 + 前端全套（日常最常用）
npm run test:watch    # 🔁 文件夹更新即自动测试（监视模式，常驻运行）
```

监视模式说明：改动 `src-tauri` 下的 `.rs` 自动跑 `cargo test`；改动 `src` 下的
`.ts/.tsx` 自动跑 `vitest`；防抖 600ms 合并连续保存；测试运行中的新变更会排队补跑。
另有两个模式：`npm run test:watch -- --all`（任何变更跑全套）、`-- --smoke`（最快冒烟反馈）。

## 二、测试类型 → 位置 → 运行方式 对照表

| 用户要求的类型 | 在本项目中的落地 | 主要位置 | 运行命令 |
|---|---|---|---|
| **单元测试** | 纯函数级测试（术语库、预处理、签名、重组、migrate、导入解析…） | 各 `.rs` 文件 `#[cfg(test)]`；`HistoryPanel.test.tsx` 纯函数 | `npm run test:rust` / `test:fe` |
| **集成测试** | 多模块协作：设置→build_manager→引擎列表；Mock引擎注入管理器；组件↔mock后端 | `engines.rs` integration_*、`translation.rs` integration_*、各组件测试 | `npm run test:rust` |
| **系统测试** | 类型检查→前端构建→cargo check→Rust测试→前端测试 五步全链路 | `scripts/system-test.mjs` | `npm run test:system` |
| **验收测试** | 用户故事级断言（指定引擎翻译、批量结果对齐、语言列表完整、设置保存链路、划词翻译链路） | `engines.rs`/`translation.rs` acceptance_*、`App.test.tsx` | `npm run test:accept` |
| **功能测试** | 各页面功能行为：翻译、搜索、删除、清空、添加术语、方案切换 | `TranslatePanel/HistoryPanel/TermsPanel.test.tsx` | `npm run test:fe` |
| **非功能测试** | 性能+安全+可用性三类合计（见下三行），属非功能需求验证 | 见下三行 | — |
| ├ **性能测试** | 时间预算断言：100KB预处理、500术语×50KB替换、万行重组、2万条过滤 | `*_perf_*`（Rust）、HistoryPanel 性能用例 | `npm run test:perf` |
| ├ **安全测试** | RFC3986签名编码防注入、恶意JSON导入、损坏/缺字段settings安全回退、XSS按文本渲染、密钥往返 | `*_security_*`（Rust）、HistoryPanel/TranslatePanel 安全用例 | `npm run test:security` |
| └ **可用性测试** | 自动化代理：空态文案、错误提示可读、禁用态+title说明、加载反馈、菜单高亮 | 各前端测试中标"可用性"的用例 | `npm run test:fe` |
| **回归测试** | 针对历史bug的防复发用例（详见第四节） | `*_regression_*`、App 回归用例 | `npm run test:accept` |
| **冒烟测试** | 核心链路快测：单引擎翻译、无引擎报错、组件能渲染 | `smoke_*`（Rust）、describe 里带 Smoke 的用例 | `npm run test:smoke` |
| **健全性测试** | 环境+项目结构自检（工具链、依赖、关键文件、配置合法） | `scripts/sanity.mjs` | `npm run test:sanity` |
| **黑盒测试** | 组件测试：mock 后端接口，只看输入→界面输出 | 全部 `.test.tsx`（对UI是黑盒） | `npm run test:fe` |
| **白盒测试** | 直接测私有函数：make_sign、utc_date、percent_encode、make_sign_input、migrate | 各 `.rs` 模块内测试（同模块可访问私有项） | `npm run test:rust` |
| **灰盒测试** | 知道内部结构、通过公开接口测：Mock引擎注入 TranslationManager 测回退/批量对齐 | `engines.rs` integration_* | `npm run test:rust` |
| **手动测试** | GUI 交互无法自动化的部分（托盘、全局热键、截图OCR全流程） | `docs/手动测试清单.md` | 人工执行 |
| **自动测试** | 上述全部自动化用例 + 监视器 | — | `npm test` |
| **探索性测试** | 章程(charter)驱动的自由探索 | `docs/手动测试清单.md` 第五节 | 人工执行 |
| **猴子测试** | 随机怪异输入只求不崩+输出不变式（控制字符/emoji/零宽/RTL/超长/随机操作序列） | `*_monkey_*`（Rust 3个）、HistoryPanel 猴子用例 | `npm run test:monkey` |

> 真实API联调测试（百度/有道/离线模型，需密钥与网络）保留为 `#[ignore]`，
> 显式运行：`cargo test -- --ignored`（需设置 BAIDU_APP_ID 等环境变量）。

## 三、文件清单

```
tauri-project/
├─ vitest.config.ts            # 前端测试配置（jsdom）
├─ scripts/
│  ├─ watch-tests.mjs          # 🔁 监视器（文件夹更新即测试）
│  ├─ sanity.mjs               # 健全性检查
│  └─ system-test.mjs          # 系统测试（五步全链路）
├─ src/
│  ├─ test/setup.ts            # 测试全局setup（cleanup、jest-dom）
│  ├─ App.test.tsx             # 回归/集成/可用性（6用例）
│  └─ components/*.test.tsx    # Sidebar 4 / TranslatePanel 9 / HistoryPanel 17 / TermsPanel 4
└─ src-tauri/src/              # Rust 测试在各模块 #[cfg(test)] 内，前缀分类
   ├─ engines.rs               # +43 用例：单元/集成(灰盒)/性能/安全/猴子/冒烟/回归/验收
   ├─ system.rs                # +14：迁移回归/健全性/安全
   ├─ terms.rs                 # +7：导入解析功能/安全
   ├─ history.rs               # +3：上限裁剪回归
   └─ translation.rs           # +6：build_manager 集成/验收
```

测试命名即分类：Rust 用前缀（`smoke_` `integration_` `acceptance_` `regression_`
`perf_` `security_` `monkey_` `sanity_`）；前端用中文标签（可用性:/安全:/猴子:/性能:/回归:/Smoke）。

## 四、回归测试覆盖的历史 bug

| 历史 bug | 防复发用例 |
|---|---|
| 有道 salt 秒级重复被判重放(207) | 沙盒内签名输入规则测试 + 真实API联调测试（ignored） |
| 设置页永远"加载中…"（loadSettings 丢失 setLocalSettings） | `App.test.tsx` 回归：加载完成后"加载中…"消失；失败给提示 |

| 百度合并请求行数不齐打乱截图逐行覆盖 | `regression_baidu_batch_preserves_line_alignment`、`integration_batch_baidu_mismatch_falls_back_to_per_line` |
| 历史记录无限增长 | `test_history_capped_at_500` |
| 旧配置字段迁移（tesseract/argos/copy组件/overlay/当前翻译源） | `system.rs` 迁移回归组 |

## 五、约定

1. **测试不碰真实数据文件**：terms.json/settings.json/history.json 位于 exe 同目录，
   自动化测试一律走纯函数或 mock，绝不读写（避免污染开发/用户数据）。
2. **性能预算宽松**（debug 构建下 2~10s），防止 CI/低配机抖动误报；数量级劣化才会触发。
3. **真实数据安全**：导入解析、设置反序列化的安全测试覆盖恶意/损坏输入，验证"拒绝而非崩溃"。
4. GUI 端到端（托盘/热键/截图OCR）在无显示器环境不可自动化 → 见手动清单。
