# 手动测试清单（GUI / 可用性 / 探索性 / 验收）

> 以下用例无法在无界面环境自动化（托盘、全局热键、屏幕截图OCR、真实引擎联调）。
> 每次发版前按顺序过一遍，约 30~40 分钟。截图翻译类用例需要 Windows 10/11。

## 一、系统级冒烟（发版必做，5分钟）

| # | 步骤 | 预期 |
|---|---|---|
| 1 | 双击启动 smart-translator.exe | 主窗口按"上次大小"打开；无报错弹窗 |
| 2 | 再次双击 exe（单实例） | 不出现第二个实例，已有窗口被唤起 |
| 3 | 点窗口 × | 隐藏到托盘（不退出）；托盘图标存在 |
| 4 | 托盘左键 | 主窗口重新显示 |
| 5 | 托盘右键 → 退出 | 进程完全退出（任务管理器确认） |
| 6 | 断网后启动，翻译一段文本 | 离线引擎兜底或给出可读错误，不崩溃 |

## 二、功能验收清单（核心用户故事）

**翻译主流程**
- [ ] 输入英文点"翻译"，出现译文、所用引擎名、网络延迟指示
- [ ] 空输入点"翻译"提示"请输入要翻译的内容"，不调用后端
- [ ] `MiniMap and Mini_Map test` 示例按钮 → 分词为 Mini Map（预处理生效）
- [ ] 点击引擎徽章变为选中态（✓），翻译走指定引擎；再点取消回到自动
- [ ] 源语言=自动检测时 ⇄ 交换按钮禁用；手动选语言后可交换并自动重译

**术语管理**
- [ ] 添加术语 server→服务器，翻译含 server 的文本，译文应用术语
- [ ] 重复添加同一译法静默跳过；删除术语后不再应用
- [ ] 导入两列 CSV / Tab 分隔 TXT / JSON 三种格式都成功；坏 JSON 报"JSON 解析失败"
- [ ] 内置符号纠错包：方案一勾选时 乛→→ 生效；切到方案二不生效
- [ ] 至少保留一个方案：删到最后一个方案时报错拒绝

**截图翻译**（需真实屏幕）
- [ ] 全局热键 Ctrl+Alt+S 触发截图；ESC 可退出
- [ ] 框选后 OCR 出文字并覆盖译文；译文可复制原文/译文
- [ ] 设置页调整菜单组组件顺序，截图菜单顺序同步变化（双向绑定）
- [ ] 切换"当前翻译源"后截图翻译使用新引擎

**设置**
- [ ] 修改设置 → 保存 → 弹"设置已保存"，重启后生效
- [ ] "恢复默认"按钮放弃当前草稿
- [ ] 输入非法热键（如 Ctrl+Alt+TCt）保存后，加载时自动回落 Ctrl+Alt+T
- [ ] 手动删坏 settings.json 再启动 → 应用用默认配置正常启动（不崩溃）

**历史**
- [ ] 每次翻译自动记录；搜索、删除单条、清空（有确认）均生效
- [ ] 记录超过 500 条后最旧的被裁剪

## 三、可用性测试脚本（找 1 名非开发者用户，观察记录）

1. 给用户任务："把一段英文截图翻译成中文"，不给任何指导，观察：
   - 能否自己发现托盘图标与热键？（记下卡点）
   - 截图框选到出译文，是否需要帮助？
2. 让用户在设置页完成"换一个翻译引擎"任务，观察能否找到入口。
3. 让用户给"bug"这个词添加自己的译法，观察术语页是否易懂。
4. 记录：误操作后能否恢复（草稿/恢复默认按钮是否被注意到）？
5. 询问打分（1-5）：易懂性、文字可读性（对比度）、操作步骤数是否可接受。

判定：任务完成率 <80% 或任一步平均耗时超预期 2 倍 → 记可用性缺陷进入迭代。

## 四、探索性测试章程（每次 30 分钟一轮，按章程自由探索）

| 章程 | 目标 | 范围与说明 |
|---|---|---|
| OCR 边界 | 找出截图识别的失效场景 | 小字/大字号/深色主题/斜体/表格/代码编辑器；记录 OCR 错误类型 |
| 语言矩阵 | 发现引擎语言支持坑 | 9 种语言两两互译抽测，注意 ru/pt/fr 等小语种与 auto 检测 |
| 输入敌对 | 尝试让输入框/导入崩溃 | 10MB 文本、纯 emoji、10万行 CSV、损坏 JSON、超长术语 |
| 多窗口竞态 | 截图会话与主窗口交互 | 截图进行中改设置/切翻译源/按热键，观察状态错乱 |
| 资源泄漏 | 长时间使用变卡？ | 连续截图 30 次观察内存；历史 500 条满载时界面流畅度 |

产出：每轮记录"发现清单"（现象、复现步骤、严重级），转成 bug 或自动化用例。

```bash
$env:BAIDU_APP_ID="..."; $env:BAIDU_SECRET="..."

```
